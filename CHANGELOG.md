## Система термического сканирования MirorSkaner

### Описание проекта

MirorSkaner - это кроссплатформенное приложение для автоматизированного термического сканирования, разработанное на языке Rust с использованием фреймворка Iced для графического интерфейса. Приложение обеспечивает управление контроллером STM32F415RGT6, работу с ИК-камерой Optris PI 640 и автоматическое сканирование образцов по концентрическим траекториям.

### Архитектура проекта

Проект построен по модульному принципу с четким разделением ответственности:

- **app/** - Управление состоянием и основная логика приложения
- **ui/** - Компоненты пользовательского интерфейса (Iced)
- **hardware/** - Работа с оборудованием (контроллер STM32, камера Optris)
- **processing/** - Бизнес-логика (сканирование, анализ)
- **config/** - Управление конфигурацией (INI файлы с hot-reload)
- **data/** - Работа с данными и экспорт
- **utils/** - Вспомогательные утилиты (углы, единицы измерения)

### Найденные и исправленные проблемы

#### Реорганизация структуры проекта

**Проблема**: Файлы находились в корне `src/`, не соответствуя модульной архитектуре из ТЗ.

**Решение**: Выполнена реорганизация согласно ТЗ:
- Создана структура папок app/, ui/, hardware/, processing/, config/, data/, utils/
- Модули перемещены в соответствующие папки
- Обновлены все импорты и зависимости

#### Создание конфигурационных файлов

**Проблема**: Отсутствовали конфигурационные файлы, требуемые ТЗ.

**Решение**: Созданы все необходимые конфигурационные файлы:
- `config/config.cfg` - основная конфигурация приложения
- `config/config_scan.cfg` - конфигурация сканирования
- `config/calibration_cam.cfg` - конфигурация калибровки камеры
- `config/calibration_controll.cfg` - конфигурация механической калибровки

### Изменения архитектуры и ключевые решения

#### Модульная архитектура

Проект использует модульную архитектуру с четким разделением ответственности:
- **App Layer**: Управление глобальным состоянием, координация модулей
- **UI Layer**: Специализированные компоненты для каждой функциональности
- **Hardware Layer**: Абстракции для работы с оборудованием
- **Processing Layer**: Генерация траекторий, анализ данных

#### Асинхронная архитектура

Использование Tokio для асинхронных операций:
- Асинхронная работа с COM-портом
- Неблокирующий опрос камеры
- Параллельная обработка данных

#### Система конфигурации

- INI-файлы с поддержкой hot-reload
- Автоматическое создание дефолтных конфигов
- Thread-safe доступ к конфигурациям через Arc<RwLock>

### Руководство пользователя

#### Запуск приложения

```bash
cargo run
```

#### Настройка конфигурации

Основные параметры настраиваются в файле `config/config.cfg`:

```ini
[app]
version = 1
data_dir = ./data
logs_dir = ./logs

[io]
controller_poll_ms = 5
camera_poll_ms = 10
serial_read_timeout_ms = 50
```

#### Калибровка системы

1. **Калибровка контроллера**:
   - Подключитесь к COM-порту контроллера
   - Выполните команду HOME для калибровки оси X
   - Параметры сохраняются в `config/calibration_controll.cfg`

2. **Калибровка камеры**:
   - Подключите камеру Optris PI 640
   - Используйте интерактивную панель калибровки
   - Выберите минимум 4 реперные точки
   - Калибровка сохраняется в `config/calibration_cam.cfg`

#### Выполнение сканирования

1. Настройте параметры сканирования в `config/config_scan.cfg`:
   ```ini
   [scan]
   radius_mm = 50.0
   pitch_mm = 0.25
   angle = 0:1:0
   dwell_ms = 250
   order = concentric
   fast_image_mode = true
   ```

2. Перейдите в раздел "Scanning"
3. Убедитесь, что контроллер и камера подключены
4. Нажмите "Start Scan"

Результаты сохраняются в:
- `data/temperatur_reader.md` - Markdown формат
- `data/temperatur_reader.txt` - CSV формат

### Форматы конфигурационных файлов

#### config.cfg
Основная конфигурация приложения:
- `[app]` - версия, директории данных и логов
- `[io]` - параметры ввода/вывода (таймауты, частоты опроса)

#### config_scan.cfg
Конфигурация сканирования:
- `radius_mm` - радиус сканирования в миллиметрах
- `pitch_mm` - шаг между точками
- `angle` - угол в формате d:m:s или градусы
- `dwell_ms` - задержка стабилизации в миллисекундах
- `order` - порядок сканирования (concentric/spiral/grid)
- `fast_image_mode` - быстрый режим обработки изображений

#### calibration_cam.cfg
Калибровка камеры:
- `model` - модель камеры
- `transform` - матрица преобразования 3x3 (9 элементов)
- `roi` - область интереса в формате x0,y0,w,h
- `cell_size_px` - размер ячейки в пикселях
- `version` - версия калибровки

#### calibration_controll.cfg
Механическая калибровка:
- `steps_per_rev` - шагов на оборот шагового двигателя
- `lead_screw_pitch_mm` - шаг резьбы в миллиметрах
- `microsteps` - количество микрошагов
- `pulses_per_mm` - импульсов на миллиметр
- `encoder_cpr` - импульсов на оборот энкодера
- `pulses_per_degree` - импульсов на градус
- `homing_speed_mm_s` - скорость калибровки в мм/с
- `homing_offsets_mm` - смещения калибровки x,y

### Рекомендации по настройке и оптимизации

#### Производительность

1. **Быстрый режим камеры**: Используйте `fast_image_mode = true` для снижения задержек
2. **Частота опроса**: Настройте `controller_poll_ms` и `camera_poll_ms` в зависимости от требований
3. **Буферизация**: Увеличьте буферы для высокоскоростного сканирования

#### Надежность

1. **Таймауты**: Установите адекватные таймауты для вашего оборудования
2. **Повторные попытки**: Реализуйте логику повторных попыток для критических операций
3. **Логирование**: Включите детальное логирование для отладки

#### Безопасность

1. **Валидация данных**: Все входные данные проверяются перед использованием
2. **Обработка ошибок**: Graceful degradation при частичных отказах
3. **Резервное копирование**: Регулярно сохраняйте калибровочные данные

### Известные ограничения

1. **Камера Optris**: Требует наличия PIX Connect и правильно настроенного IPC
2. **COM-порт**: Поддержка только нативных COM-портов (без виртуальных)
3. **Платформы**: В настоящее время оптимизировано для Windows, Linux требует дополнительной настройки
